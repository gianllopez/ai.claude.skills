# Design System Factory

A structured repository of best practices for creating, extending and auditing the design system of a company brand, optimized for agents, LLMs, and human designers and developers.

## Structure

- `SKILL.md` - What the skill governs, when to apply it, the workflow and the quick reference
- `rules/` - Individual rule files (one per rule)
  - `_sections.md` - Index of all rules, grouped by section in compilation order
  - `_template.md` - Template for creating new rules
  - `<prefix>-<name>.md` - Individual rule definitions
- `metadata.json` - Document metadata (version, author, abstract, reference links)
- `AGENTS.md` - Generated compiled output (all rules expanded). Never hand-edit

## Scope

The system this skill describes is brand-level: it defines how every piece derived from the brand must look and be written — tokens, components, stationery, digital documents, email, social and slide templates. Websites, apps, real presentations and personalized pieces are derived designs built from it, never part of it.

- **Colombian by design.** Every brand built with this skill is a Colombian company, so the formats for money, dates, time and phones and the legal references (_Cámara de Comercio_, _DIAN_) are fixed. The form of address, the number of brand colors and every identity value come from each brand's intake
- **One worked reference.** The _ASK TECHNOLOGY S.A.S._ (_ASKIT_) system resolves every rule. A new brand reuses its method and structure, never its values

## Using the Skill

1. Load the skill when starting, changing or auditing a brand design system
2. Follow the workflow in `SKILL.md` (intake, foundations, brand assets, components, communication pieces, print, publish, close)
3. Read the rule files of the section you are working on, or `AGENTS.md` for the complete guide
4. For a new brand, keep the method, scales and rules, and replace the _ASKIT_ values with the ones gathered in the intake

## Workflow

1. **Define rules:** create or edit markdown files in `rules/`
2. **Regenerate:** rebuild `AGENTS.md` from the rules (see below). It is a generated artifact — edit the rules, not `AGENTS.md`
3. **Format:** run `prettier --write` on each file that was modified
4. **Deploy:** distribute `AGENTS.md`

## Creating a New Rule

1. Copy `rules/_template.md` to `rules/<prefix>-<name>.md`
2. Choose the category prefix from the table above
3. Fill in the frontmatter (`title`, `impact`, `description`, `tags`)
4. Provide clear _Incorrect_ vs _Correct_ examples, using the _ASKIT_ reference where it helps
5. Register the rule in `rules/_sections.md` (section + order)
6. Regenerate `AGENTS.md`

## Regenerating `AGENTS.md`

There is no build script. `AGENTS.md` is regenerated by following the described procedure in `skill-factory/SKILL.md` (_AGENTS.md Compilation_) — reading `rules/`, `rules/_sections.md`, and `metadata.json`, then producing the compiled document. The sources of truth are the rules and `metadata.json`.

Three details fail silently if they are missed:

- The `abstract` is stored as plain text in `metadata.json`; _ASK TECHNOLOGY S.A.S._ and _ASKIT_ are italicized during compilation
- The `> **Note:**` block carries a hard line break — two trailing spaces — on every line but its last, so it renders with the same shape as the sibling skills
- From section 10 on, the rule lines of the table of contents are indented four spaces, not three, so they stay nested under the two-digit number; with three, _Prettier_ renumbers the section and breaks the list
