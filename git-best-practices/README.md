# Git Best Practices

A structured repository of version-control conventions, optimized for agents, LLMs, and human developers. It doubles as the executor for `/commit`, the one convention here that also runs as an action.

## Structure

- `rules/` - Individual rule files (one per rule)
  - `_sections.md` - Index of all rules, grouped by section
  - `_template.md` - Template for creating new rules
  - `<prefix>-<name>.md` - Individual rule definitions
- `metadata.json` - Document metadata (version, author, abstract, reference links)
- `AGENTS.md` - Generated compiled output (all rules expanded). Never hand-edit

## Workflow

1. **Define rules:** create or edit markdown files in `rules/`
2. **Regenerate:** rebuild `AGENTS.md` from the rules (see below). It is a generated artifact — edit the rules, not `AGENTS.md`
3. **Deploy:** distribute `AGENTS.md`

## Creating a New Rule

1. Copy `rules/_template.md` to `rules/<prefix>-<name>.md`
2. Choose the category prefix (`msg-`, `branch-`, and future ones such as `merge-`, `tag-`, `pr-`)
3. Fill in the frontmatter (`title`, `impact`, `description`, `tags`)
4. Provide clear _Incorrect_ vs _Correct_ examples
5. Register the rule in `rules/_sections.md` (section + order)
6. Regenerate `AGENTS.md`

## Regenerating `AGENTS.md`

There is no build script. `AGENTS.md` is regenerated by following the procedure described in `skill-factory/SKILL.md` (_AGENTS.md Compilation_) — reading `rules/`, `rules/_sections.md`, and `metadata.json`, then producing the compiled document. The sources of truth are the rules and `metadata.json`.

## The `/commit` Command

Unlike the rest of this skill, `/commit` is not only a convention to check against — it is a procedure the agent runs. Its steps live in `SKILL.md` under **Executing `/commit`**, and it enforces `rules/msg-conventional-commits.md` when generating the message.
